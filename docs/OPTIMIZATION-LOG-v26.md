## 2. 优化项详情

### 优化 1：工具本体"开箱即用"（核心）

**改动**：`tool/index.html` 在 `</script></body>` 前追加 1.5KB 启动脚本

**核心逻辑**：
```js
(function() {
  const STORAGE_KEY = 'relationship_detective_data';
  if (localStorage.getItem(STORAGE_KEY)) return;  // 已有数据，跳过
  
  // 8 位示例联系人 + 7 条互动 + 6 对连接
  const SAMPLE = { contacts: [...], ... };
  localStorage.setItem(STORAGE_KEY, JSON.stringify(SAMPLE));
  setTimeout(() => location.reload(), 100);  // 让工具本体重新渲染
})();
```

**改进效果**：
- ✅ 用户双击 → 立即看到 8 位真实感联系人
- ✅ 完整的看板 / 图谱 / 时间线 / 标签 / 关键信息 / 互动
- ✅ 不需要任何导入操作
- ✅ 已有数据时自动跳过（不覆盖用户数据）

**为什么用 location.reload() 而不是直接调 renderAll()？**
- 工具本体的 renderAll() 在 IIFE 内，未导出到全局
- reload() 是最安全的"重启渲染"方式
- 100ms 延迟让 localStorage 写入完成

### 优化 2：主站全局错误处理

**改动**：`site/assets/js/main.js` 末尾追加 50 行错误处理模块

**捕获的错误类型**：
- ✅ `window.onerror` —— 同步 JS 错误
- ✅ `unhandledrejection` —— Promise 拒绝
- ✅ 友好的 toast 提示（"页面出现小问题，已自动恢复"）

**视觉效果**：
- 错误时不再白屏
- 玻璃拟态 toast 提示（右下角，自动 3s 消失）
- 通过 `window.rhToast()` API 暴露给其他脚本使用

## 3. 性能 / 可维护性 / 边界 处理

| 类别 | 改进 |
|---|---|
| **性能** | 启动脚本只在 localStorage 为空时执行（检测后立即 return，零开销）|
| **可读性** | 启动脚本有完整注释，结构清晰 |
| **可维护性** | 错误处理模块独立 IIFE 隔离，window.rhToast 暴露 API |
| **边界** | try/catch 包裹 localStorage 操作（隐私模式 / 满容量时优雅降级）|
| **错误恢复** | 错误提示用户"已自动恢复"而非崩溃 |

## 5. 兼容性 & 风险

| 项 | 说明 |
|---|---|
| **数据迁移** | 已有数据的用户不受影响（脚本检测后 return）|
| **隐私模式** | localStorage 不可用时，try/catch 降级，工具可正常使用但无预装 |
| **旧浏览器** | try/catch + ES6 IIFE 兼容 IE11+（不含 IE）|
| **重复预装** | 已有数据时直接 return，不会重复 |
